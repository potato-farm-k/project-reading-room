# Project Reading Room UI v2 Design Guide

## 디자인 목표

UI v2는 여러 프로젝트의 기준 문서와 학습 기록을 오래 읽기 위한 개인 지식 아카이브다. 첫 화면은 홈페이지처럼 공간의 성격을 설명하되, 장식보다 문서 탐색과 읽기 흐름을 우선한다. 기존 UI와 데이터는 유지하며 새 레이아웃을 독립적으로 실험한다.

## 스타일 방향

- 문서 사이트의 명확한 정보 구조와 안정적인 사이드바를 참고한다.
- 개인 노트 도구의 따뜻한 여백과 차분한 종이 질감을 참고한다.
- 생산성 도구의 정밀한 구분선, 작은 메타데이터, 절제된 상태 표현을 참고한다.
- 특정 제품의 화면을 복제하지 않고 Reading Room의 문서 구조에 맞게 재해석한다.

## 색상 원칙

- 따뜻한 회백색을 전체 배경으로 사용하고 본문은 흰색에 가깝게 유지한다.
- 짙은 녹색은 링크, 선택 상태, 작은 강조에만 사용한다.
- 본문은 충분히 어두운 중성색으로 표시하고 보조 정보는 명도 차이로 계층을 만든다.
- 카테고리와 타입은 낮은 채도의 배지로 구분하며 색에만 의미를 의존하지 않는다.

## 타이포그래피 원칙

- UI v2에는 Pretendard를 우선 적용하고 시스템 한글 글꼴 fallback을 제공한다.
- 긴 본문의 행간은 넉넉하게, 한 줄 폭은 약 780px 안쪽으로 제한한다.
- 제목은 크기와 여백으로 계층을 만들고 본문에서 과도한 굵기 변화를 피한다.
- 코드에는 고정폭 글꼴을 사용해 일반 문장과 분명히 구분한다.

## 레이아웃 원칙

- 상단에는 공간의 이름과 Classic UI 링크를 고정 배치한다.
- 데스크톱은 탐색 사이드바와 읽기 본문의 2열 구조를 사용한다.
- Root Index는 `library.json`의 카테고리 최초 등장 순서와 문서 순서를 그대로 따른다.
- 문서 화면은 제목·설명·메타데이터 뒤에 Markdown 본문을 배치한다.

## 컴포넌트 원칙

- 검색, 카테고리 필터, 문서 목록은 사이드바에서 한 흐름으로 이어진다.
- 선택 상태는 배경색과 텍스트 색을 함께 바꿔 식별한다.
- Root Index 카드는 제목, 설명, 타입, 경로를 빠르게 훑을 수 있게 구성한다.
- 표는 좁은 화면에서 가로 스크롤이 가능하고 키보드 포커스를 받을 수 있어야 한다.
- 링크와 버튼은 키보드 포커스가 분명하게 보여야 한다.

## 모바일 대응 원칙

- 900px 이하에서는 탐색 영역과 본문을 세로로 쌓는다.
- 문서 목록은 제한된 높이 안에서 스크롤되어 본문까지의 이동을 방해하지 않는다.
- 600px 이하에서는 문서 카드와 목록을 1열로 바꾸고 메타데이터를 재배치한다.
- 최소 화면 폭은 320px이며 가로 스크롤은 표와 코드 블록 내부로 제한한다.

## 인쇄 / PDF 원칙

- 인쇄 시 상단 헤더, 탐색 사이드바, 조작 도구를 숨긴다.
- 본문은 흰 배경과 검정 텍스트를 사용하고 화면용 그림자를 제거한다.
- 제목 뒤 페이지 분리와 표 행 내부 분리를 피한다.
- 표 테두리와 코드·인용 블록의 구획은 흑백에서도 유지한다.
- 링크 URL을 본문 뒤에 자동 노출하지 않아 긴 경로가 읽기 흐름을 방해하지 않게 한다.
